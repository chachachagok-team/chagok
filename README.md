# 차곡차곡 — 달리는 타임캡슐

여행의 경로와 들른 음식점·휴게소, 사진, 그리고 그 자리에서 말로 남긴 이야기까지 차가 알아서 차곡차곡 기록해 두었다가, 다음에 같은 길을 지날 때 먼저 꺼내 주는 Pleos Connect 차량용 앱입니다.

현대자동차그룹 차량용 앱 개발 공모전 출품작 · 팀 차곡

## 핵심 기능

| 기능 | 차에서 가져오는 정보 |
|---|---|
| 자동 여행 기록 — 출발·도착을 알아서 판단하고 경로·거리·동승자를 여행 카드 한 장으로 | 내비게이션 목적지·즐겨찾기, 위치, 기어, 주행거리 |
| 들른 곳 기록 — 멈췄다 출발한 곳을 경로 위에 순서대로 | 기어(정차→출발), 위치, 내비게이션 주소 |
| 정차 후 한마디 — P→D 순간 차가 상황에 맞게 묻고, 대답을 글자로 그 장소에 저장 | 기어, 좌석(탑승 인원), 와이퍼(비), 시각 |
| 함께 채우는 사진첩 — 동승자가 QR로 사진을 한곳에 | 진행 중인 여행과 자동 연결 |
| 다시 지날 때 먼저 꺼내기 — 작년 이야기를 짚으며 "들렀다 갈까요?" | 위치, 내비게이션 |

## 실행 방법

### 요구 환경
- Android Studio (최신 버전)
- Pleos Connect Emulator v2.1.0 (API 34) · 화면 규격 2560×1440, 160dpi
- JDK 17 이상 (Android Studio 내장 JDK 사용 권장)
### 에뮬레이터 준비
1. Pleos Playground(개발자 포털)에서 **Pleos Connect Emulator**를 내려받아 설치합니다.
2. 에뮬레이터를 실행하면 Android Studio의 기기 목록에 잡히고, `adb devices`에서도 보입니다.
3. 기어(P/D)·가속 등 차량 신호는 **가상 차량 콘솔**(브라우저)에서 조작합니다. 콘솔은 포트 포워딩 후 브라우저로 엽니다.
```powershell
# Windows (PowerShell)
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" forward tcp:8088 tcp:8088
```

그다음 브라우저에서 `http://127.0.0.1:8088/` 에 접속하면 기어·가속 등을 조작할 수 있습니다. 이 앱은 기어 신호로 정차·출발을 판단하므로, 시연 진행도 이 콘솔로 합니다.

### APK로 바로 설치
APK 위치: **`apk/차곡_차곡차곡_release.apk`** (서명된 release 빌드)

Pleos Connect 에뮬레이터에 설치합니다.

```
adb install -r "apk/차곡_차곡차곡_release.apk"
```

### 소스에서 빌드
1. 이 저장소를 클론해 Android Studio로 엽니다.
2. 프로젝트 루트의 `local.properties`에 Pleos 음성 SDK 키를 추가합니다(없어도 빌드·실행은 됩니다. 음성 엔진 연동 시에만 필요).
```
pleos.clientId=YOUR_CLIENT_ID
pleos.clientSecret=YOUR_CLIENT_SECRET
```
3. Pleos Connect 에뮬레이터를 실행 대상으로 선택하고 Run 합니다.
   ※ 사진 QR(동승자 사진 업로드) 기능은 업로드 서버 키 파일 `app/src/main/assets/appsscript_key.txt` 를 사용하는데, 보안상 저장소에는 포함하지 않았습니다. 소스 빌드에서는 이 키가 없어 QR 생성만 동작하지 않고 나머지 기능은 모두 동작합니다. **전체 기능을 보시려면 `apk/`의 APK 설치를 권장합니다** (키 포함).

## 시연(예시 여행) 돌려 보기

시연 영상과 같은 흐름(집 → 천안삼거리휴게소 → 대전 성심당 → 충주호 → 집)을 에뮬레이터에서 직접 볼 수 있습니다.

> 처음 설치했다면: 첫 실행에서 위치 권한을 **허용**한 뒤 **앱을 한 번 다시 시작**해 주세요. 권한 승인 전에 그려진 화면은 지도·기록이 비어 보일 수 있습니다.

1. 홈 오른쪽 아래 **[여행 시작]** 버튼을 누릅니다. 시연 설정(`VoiceRules.DEMO_SCENARIO = true`, 기본값)에서는 이 버튼이 바로 예시 여행으로 이어집니다.
2. 탑승자를 고르고 출발합니다.
3. 진행은 에뮬레이터 가상 차량 콘솔의 **기어(P/D)** 로만 합니다.
   - **D**: 다음 목적지로 달립니다. 지도에 경로가 그려집니다.
   - 화면에 "거의 다 왔어요"가 나오면 **P**: 도착 처리(안내 카드·질문)가 이어집니다.
4. 천안삼거리휴게소 3km 앞에서 작년 이야기가 나오고, 정차 후 다시 출발할 때마다 차가 질문합니다. 집에 도착하면 여행 요약과 사진 QR이 뜹니다.
   앱을 다시 켜면 지난 테스트 기록이 초기화되어 처음부터 다시 돌릴 수 있습니다(`VoiceRules.DEMO_FRESH_START`).

그 밖의 점검 도구(차량 신호 값 보기, 시연 준비 초기화 등)는 홈 왼쪽 패널의 제목 "달리는 타임캡슐"을 **길게 누르면** 열리는 테스트 화면에 있습니다. 영상에 보이지 않도록 버튼을 숨겨 두었습니다.

## 사용한 Pleos SDK

| SDK | 용도 | 상태 |
|---|---|---|
| Vehicle | 기어·주행거리·좌석·와이퍼 | 동작 확인 |
| Fused Location | 현재 위치, 경로 기록 | 동작 확인 |
| NaviHelper | 목적지·최근 목적지·즐겨찾기, 경유지 추가 | 목적지·위치 동작 확인, 경유지는 실기 검증 예정 |
| TTS / STT (Gleo AI) | 질문 읽어 주기, 대답 글자 변환 | 공식 문서대로 연동 완료, 엔진 공개 대기 |
| LLM (Gleo AI) | 제안 문장·여행 요약 생성 | 연동 코드 작성 완료, 엔진 공개 대기 |

※ 제출 시점의 개발 환경에서는 TTS·STT·LLM 엔진이 제공되지 않아(콘솔 'Coming Soon'), 시연 모드(`VoiceRules.DEMO_RECORDINGS`)에서는 같은 흐름을 미리 준비한 예시 음성·문장으로 대체합니다. 엔진이 열리면 플래그 전환만으로 실제 음성 흐름으로 동작합니다.

※ 시연에 쓰인 사진·음성은 AI로 생성한 예시이며, 앱은 마이크로 직접 녹음하지 않습니다(음성 기능은 Pleos 문서 방식만 사용).

## 기술 스택

- Kotlin · Jetpack Compose
- MapLibre (OpenStreetMap) — 지도·경로·사진 핀 직접 구현
- ZXing — 사진 모으기 QR 생성
- 사진 업로드: QR로 여는 웹 페이지(외부 서버)로 동승자 휴대폰에서 업로드
## 프로젝트 구조

```
app/src/main/java/com/familyvoice/app/
├── MainActivity.kt    # 차량 신호 처리, 여행 판단, 질문·저장 흐름, 예시 여행 진행
├── HomeScreen.kt      # 홈(기억 지도)·회상 카드 UI
├── TripScenario.kt    # 예시 여행 경로·단계 정의
├── Journal*.kt        # 여행·장소 기록과 여행 탭 UI
├── PleosVoice.kt      # Pleos TTS·STT·LLM 연동
├── TripUpload.kt      # 사진 QR(여행 링크) 생성
└── VoiceRules.kt      # 동작 규칙·시연 플래그 모음
```
